## Bugs found

Three bugs, three fixes.

1. **Undefined variable $customerId in CheckoutService.**
   Caught by PHPStan. placeOrder() has $customer, not
   $customerId. Fixed by guarding on
   `$customer instanceof Customer` and passing $customer->id.

2. **CheckoutService constructor argument count mismatch.**
   Caught by PHPStan. The provider binding was not updated
   for the new 15th dependency. Fixed by adding
   `$c->get(CustomerNotificationService::class)` to the
   binding.

3. **Header partial silently vanished.** A patch removed
   the block at the top of the header partial that defined
   $__customer and $__unread. Every page threw "Undefined
   variable $__unread", view_partial() caught it, logged
   it, and returned an empty string. The entire header
   disappeared from every storefront page.

   Caught by:
     ERROR: view_partial(storefront/partials/header)
     failed: Undefined variable $__unread

   Documented as Pattern 30 in docs/REMEMBER.md. Pattern
   30 completes the shared-partial failure triangle:
   Pattern 26 (guard no-ops on a second caller), Pattern
   28 (partial does not inherit outer scope), Pattern 30
   (partial references a variable removed by a patch).

Bugs 1 and 2 are the reason the wiring step is its own
commit. Bugs caught in wiring are cheaper than bugs caught
in the smoke test.

## Decisions made

- **Self-contained Commerce feature.** No cross-layer
  writes. No core_notifications reads. No
  NotificationRuleService. Preferences stored as two
  boolean columns on commerce_customers. Documented in the
  plan's opening section.

- **Bell dropdown added mid-build.** The original plan
  called for a badge in the sidebar. The customer asked
  for a header bell that previews unread inline. Added as
  customer_recent_messages() helper plus the bell panel.

- **Header action cluster reordered.** Search, cart, bell,
  account. Cart first because it is most-used. Account
  last because it is least-frequent.

- **Guest sign-in label.** The bare person icon did not
  communicate "click here to log in." Guests now see a
  "Sign in" text label. Collapses below 640px.

- **Email channel is a stub.** The preference is stored,
  no send. 010 ships the digest worker.

- **Order Updates tab may be empty.** CheckoutService
  writes one row per order placed. When 008H and 010
  introduce real order lifecycle events, they add
  producers at their own call sites.

## Next session opens with

Open 008G.4 (PWA). This was deferred from the original
008G scope. Scope in docs/ROADMAP.md.

The PWA sub-stage is unlike the last three:

- No new database tables. No new service. No new
  controller.
- A web app manifest (`/manifest.webmanifest` per store).
- A service worker (`/service-worker.js`).
- Offline fallback page.
- Install prompt handling.
- Icon set (must be generated or supplied).
- A `<meta name="theme-color">` tag driven by the store
  branding.

The existing storefront controllers already resolve the
store. The manifest controller probably extends
StorefrontController for consistency but the manifest
endpoint is not a page - it returns JSON, not HTML.

Icon assets and manifest scope per store (multi-tenant
consideration) need a decision. The manifest URL likely
becomes `/manifest-{store-slug}.webmanifest` or is
served at a fixed path with the store resolved from the
request host.

Read the PWA design before writing any code. This is the
first stage that ships zero PHP application logic - just
public assets, HTTP headers, and one small JSON endpoint.
