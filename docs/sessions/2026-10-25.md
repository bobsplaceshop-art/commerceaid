## Bugs found

- **`config[config[headline]]` double-wrap** — `show.php` and
  `_config-field.php` both wrapped the field name. Every
  block config field silently discarded its value. Pattern
  23 (cascade check before every patch).
- **`/media/{id}/...` URL from a numeric file id** — seven
  sites (hero, banner, promo-panel, MerchantFeed,
  SocialMeta 2x, StructuredData). Image would 404 with no
  error message. Pattern 46.
- **Product og:image relative URL** — the docblock said
  scrapers silently ignore it. Every product share preview
  since the SEO stage has been broken. Pattern 46 follow-up.
- **"Pencil dead after drag"** — the settings click was
  bound per-element on load; `rerenderSidebar()` replaced
  the buttons and lost the handler. Pattern 26 (shared
  partial guards reflect the partial's own requirement) /
  event delegation.
- **"Drag does nothing, stop sign"** — no
  `dataTransfer.dropEffect = 'move'`, no `dragenter`
  preventDefault, no rerender. Pattern 4.
- **`$renderBlockRow` inline markup duplicated in JS** —
  caught before commit by the "don't risk drift" pushback.
  Replaced with a shared `<template id="tpl-block-row">`.
- **"Headline is required" on a visibly-filled field** —
  the JSON preview fetched with `.json()` threw on the raw
  HTML error response. Root cause was the double-wrap; the
  symptom was a console parse error. Pattern 32.
- **`?> inside a docblock of `bin/check-media-urls.php`** —
  `**/*.php` closed the PHP comment. Pattern 39.

## Decisions made

- **`<template id="tpl-block-row">` is the single source
  of row markup.** Both PHP (initial render via inline
  script) and JS (`rerenderSidebar()`) clone it via
  `window.__builderFillRow`. A future change to the row is
  one edit, not two.
- **`window.__builderTree` is the single source of drag
  state.** `moveNode()` updates the tree. `dragover` does
  not mutate the DOM.
- **`PageDraftRepository::saveTree()` is the persistence
  path.** A flat map of `{id: {parent_id, sort_order}}`
  walks once. `saveReorder()` is preserved as the legacy
  fallback in `reorderBlocks()`.
- **`bin/check-media-urls.php` is a permanent prevenger
  checker.** It greps app/ and resources/ for the literal
  `/media/{id}` concatenation. `composer prevenger` now
  runs five checks, not four.
- **Delegation on document for click handling.** The
  settings pencil and mobile-close handlers are bound to
  `document`, not to elements. They survive any DOM
  rebuild.
- **No GrapesJS / PHPagebuilder adoption.** Evaluated both.
  PHPagebuilder and PHPagebuilder-style tools output
  HTML/CSS, not structured blocks; integrating them would
  require building a bridge to our `PageBlock` model. The
  client-side tree refactor was the smaller, correct
  answer.
