### The CSP form-action block

The Stripe redirect never reached Stripe's Checkout
page during the first few attempts. The customer
stayed on the confirm page after clicking Place
order.

Root cause: public/.htaccess set
`form-action 'self'`. The CSP form-action directive
governs the redirect chain that follows a form POST.
The browser silently refused the 302 to
checkout.stripe.com because it is not 'self'.

Fixed by extending the form-action allowlist to the
three payment provider origins:

  https://checkout.stripe.com
  https://www.paypal.com
  https://www.sandbox.paypal.com

This is the fix that unblocked Stripe. It will also
cover PayPal when the PayPal round trip runs.

### Country selector with self-hosted flags

The two-letter country input on the shipping step is
now a searchable dropdown with a real SVG flag next
to each country name.

  - app/Commerce/Support/CountryCatalog.php. 249
    countries from the ISO 3166-1 standard. Generated

    array. Four accessors.

  - public/assets/flags/*.svg. 249 SVG flag files

    from the storefront domain, zero external
    requests.

  - public/assets/js/country-select.js. Progressive
    enhancement. Reads the JSON payload from the
    component root, builds the list once, filters by
    typed text, keyboard navigation, click outside to
    close. No dependency.

  - The view keeps the text input in the DOM as a
    fallback for no-JS browsers. The JS hides it on
    init. The input keeps its name attribute and its
    form POST path.

  - public/assets/css/storefront-checkout.css. The
    component styles. Flag images sized to 20 by 15.

On Windows, the OS previously rendered the flag emoji
as two letters. The SVG image fixes that. Every
operating system now shows the actual flag.

### Phone validation

## Bugs found

One real bug plus three process findings.

**The CSP form-action block.** The 302 to Stripe's
Checkout page was silently refused by the browser. The
customer stayed on the confirm page. This was the
root cause of the "payment did not reach Stripe"
symptom. Fixed in 3d04b5b.

**Process finding 1: the emoji flag rendering on
Windows.** The country-select originally rendered the
emoji flag character. Windows Chrome and Edge render
emoji flags as the two-letter code, not the flag
image. Every other OS renders the actual flag. Fixed
by switching to self-hosted SVG files from Twemoji.

**Process finding 2: the seeder description was too
long for VARCHAR(500).** The first version of the
services questionnaire seeder wrote a description
around 1,800 characters. The column is VARCHAR(500).
The runner aborted on the first attempt. Fixed by
shortening the description to fit.

**Process finding 3: two zero-byte shell artifacts
in the repo root.** Names were `Bank transfer,` and
`Cash on delivery,`. A grep output pasted without
quoting caused the shell to interpret trailing commas
as redirection. Same class as the earlier `Coupon`
and `Customer Approvals` artifacts noted in session
2026-10-13-2. Both removed before the commit.

## New patterns for REMEMBER.md

**The CSP form-action directive governs the redirect
chain that follows a form POST.**

This is a distinct rule from the general CSP
`default-src` or `connect-src`. A form submission
that produces a 302 to a different origin is blocked
by `form-action 'self'` even when the response itself
is valid. The customer sees nothing. The browser
console may show a CSP violation, but the field itself
looks normal.

The fix: add every external redirect target that
follows a form POST to the `form-action` allowlist.

This joins the pattern set from the payment-provider
work. It will affect any future integration that
redirects the customer to a hosted page after a form
submit.

**Self-hosted flag assets for any country dropdown.**

The emoji flag character renders correctly on macOS,
iOS, Android, and most Linux. On Windows Chrome and
Edge it renders as the two-letter code. The
self-hosted SVG set is the portable solution. This
mirrors the pattern already established for fonts
and icons.
