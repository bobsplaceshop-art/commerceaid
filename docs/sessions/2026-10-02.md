## Bugs found

Seven bugs. Each one caught at a specific layer.

1. Container: nothing bound for MediaRepository.
   Caught by the app log on the first upload attempt.
   The repository and MediaProcessor were never
   registered in CommerceServiceProvider. This is the
   fourth "forgot to bind" bug this session. Logged as
   stage 008J.

2. Uploads silently did nothing.
   The settings form lacked enctype="multipart/form-data".
   Caught by a screenshot showing "Settings saved" but no
   preview. Fixed by adding the enctype and by making
   the save flash honest (savedCount / fileErrors).

3. Size cap not enforced.
   Caught by testing: a 2 MB file succeeded against a
   1 MB field. Fixed by capping $maxMb in the repository
   against the context spec. Independent enforcement at
   a second layer.

4. No preview after reload.
   Caught by testing. $values came from the key-value
   store; the branding fields write to commerce_stores
   columns. Fixed with mergeColumnValues() in the
   settings controller's index().

5. Duplicate label and hint.
   Caught by screenshot. _field.php and _field-file.php
   both rendered them. Fixed by stripping the outer
   wrapper from the partial.

6. PHPStan: float array keys in MediaMeta.
   The aspectRatioLabel() method used a float-keyed
   lookup. PHP truncates float keys to integers, so
   every entry collided. Caught statically at level 8.

7. PHPStan: dead dimension guard in MediaProcessor.
   A defensive check was always-false per GD's contract.
   Removed.

Bugs 1-5 were runtime. Bugs 6-7 were static. Five were
caught during browser testing, two by PHPStan.

## Decisions made

- **Split 008G.4 into three sub-stages.** Upload core
  first, media page second, PWA third. Documented in the
  amended 008G.4 plan.

- **Variant pipeline.** Every image generates WebP + JPEG
  at multiple sizes per context. Documented in the
  008G.4a plan's Image Variant Pipeline section.

- **DTOs over docblock-shaped arrays.** MediaVariantSpec
  and MediaContextSpec replaced nested array shapes. The
  original docblock approach kept surfacing PHPStan
  narrowing problems. DTOs eliminated the class of bug.

- **EXIF stripping on upload.** Phone photos carry GPS
  coordinates. Under DSGVO this is personal data.
  MediaProcessor::stripMetadata() re-encodes through GD
  to drop metadata. Added to COMPLIANCE-DE.md entry 10.

- **Commerce owns the file-store relationship.**
  core_files stays a Platform table. Store scoping is
  expressed via the existing core_entity_files
  polymorphic link. Documented in the 008G.4a.1 ROADMAP
  entry.

- **Setup wizard simplified.** The PWA fields were
  duplicated between the wizard and Store Settings.
  Single source of truth is now Store Settings. The
  wizard points there.

- **Compliance tracker created.** docs/COMPLIANCE-DE.md
  is a new living document tracking every German legal
  requirement, its exposure, how it is addressed, and
  where the code lives. 20 entries in the current map.

## Next session opens with

Open 008G.4a.1 (media library page). Scope in
docs/ROADMAP.md.

The media page is the browse/manage surface for
uploaded files. New ground vs the last three sub-stages:

  - It reads core_files (a Platform table) and
    core_media_meta + core_media_variants (Commerce
    tables).
  - It must scope listings per store. The mechanism is a
    core_entity_files link with entity_type='store' that
    every upload writes. That link does not exist yet -
    adding it is the first file of the stage.
  - It needs a thumbnails grid, filters, search, delete,
    and replace-in-place.
  - Delete must be aware of usage: a file that is
    referenced by a store logo cannot be deleted without
    first clearing the reference.

The session file lists the pieces. A pure read of the
existing MediaRepository and MediaController should be
enough to write the plan.
