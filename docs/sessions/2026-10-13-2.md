## Bugs found

1. **The bulk delete flash said "updated".** Every
   bulk action used the same flash message template.
   Delete should say "deleted". Fixed by setting a
   $verb variable in the switch.

2. **The storefront dev overlay polled the admin
   endpoint.** An admin visiting the storefront saw
   server exception banners covering the customer
   page. The storefront overlay should handle
   JavaScript errors only. Removed the fetch from
   the storefront layout; the admin layout keeps it.

3. **The debug endpoint returned INFO lines.** It
   filtered by request_id presence only. The
   form.submitted audit line carries a request_id and
   appeared in the overlay as if it were an error.
   Filtered to EXCEPTION and ERROR levels.

4. **The Python heredoc mangled \n in the CSV
   escape function.** The strpbrk character class and
   the line-ending concat wrote literal newlines into
   the PHP source instead of escape sequences. Fixed
   by using chr(10), chr(13), and PHP_EOL.

## Decisions made

- **Notifications go through NotificationService, not
  a general event bus.** The codebase has
  NotificationService::dispatch with a rule-based
  recipient resolver. That is the working
  notification infrastructure. The plan's "event"
  and "webhook" bullets assumed infrastructure that
  does not exist.

- **Defer event dispatch and webhook callout to
  009.7.** Building an event bus and a webhook
  dispatcher is a subsystem, not a Session 4 bullet.
  Both are logged in the plan doc and deferred.

- **Status and notes save in one POST.** Two separate
  forms would have needed a second route and a
  second controller action. Merging them matches the
  merchant's flow: read, decide, annotate, save.

- **The storefront overlay is JS-only.** Server
  exception polling is admin tooling. The customer
  surface does not show it.

- **The debug endpoint serves errors, not all logs.**
  INFO lines are for the log file. The overlay is for
  problems.

## New patterns for REMEMBER.md

**PHP newlines and control characters in Python
heredocs.**

When a Python script writes PHP source, backslash
escape sequences in the Python string may be
interpreted by Python or the shell before they reach
PHP. `\n` becomes an actual newline. `\r` becomes an
actual carriage return. Both corrupt PHP string
literals.

The rule: inside a Python heredoc that produces PHP
code, never write `\n`, `\r`, `\t`, or any other
backslash escape. Use `PHP_EOL`, `chr(10)`, `chr(13)`,
`chr(9)`. These are function references that survive
shell, Python, and PHP untouched.

Cost this session: one broken commit, one parse
error, one fix. Worth codifying.
