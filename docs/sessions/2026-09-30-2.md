## Bugs found

Three bugs.

1. **storeFromUpload() signature change without caller
   updates.**

   The repository method gained a required `$storeId`
   parameter. Two callers - `MediaController::upload()`
   and `SettingsController::saveFileColumn()` - initially
   still passed the old argument order. PHPStan did not
   flag it because the first argument type was unresolved
   (`$request->file()` returns `?array`), and PHPStan
   skips the remaining argument checks when it cannot
   resolve the first.

   Both callers were updated in the same patch that
   changed the signature. Caught by reading the callers
   before running the pipeline, not by PHPStan.

2. **The 'skipped' status was treated as an error.**

   When a file field was not touched in a save, the
   status string `'skipped'` returned from
   `saveColumnSetting()` was added to `$fileErrors` and
   flashed as if it were a failure. The user saw
   "skipped" in a red flash after uploading a file that
   had actually saved.

   Root cause: the save loop's outcome routing treated
   any non-'saved' string as an error. Fixed by
   distinguishing three cases: `'saved'` increments the
   count, `'skipped'` is silently ignored, any other
   string is an error.

3. **Import guard was fooled by the class name.**

   The `MediaLibraryController` import in
   `routes/commerce.php` was skipped because the patch's
   guard checked for the class name (which already
   appeared in route handler references). PHPStan caught
   it as "Class not found" on three route lines. Fixed
   by force-inserting the import.

   This is the second time this session that a "does this
   use statement exist" check was fooled by the class
   name appearing elsewhere in the file.

## Decisions made

- **Store scoping via core_entity_files.** `core_files`
  stays a Platform table. Commerce expresses the
  file-to-store relationship via the existing
  polymorphic link table. No schema change.

- **No backfill for existing uploads.** The two files
  uploaded during 008G.4a have no entity_files link and
  will not appear in the media library.

- **Uploads happen at the point of use, not from the
  media page.** The library is browse + manage.

- **Delete is guarded by usage.** A file referenced by
  any entity cannot be deleted from the media page.

- **Replace-in-place deferred.** Real complexity.
  Its own sub-stage if needed.

- **Media nav item under Catalog, not a new Content
  group.**

- **One delete route.** The old
  `POST /commerce/ca-admin/media/delete` was retired.
