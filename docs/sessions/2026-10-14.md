## Worked on

- **A new checker: bin/check-responsive.php.**
  Three rules, all statically detectable.

    1. Inline <style> blocks in views must not
       contain @media queries. Media queries belong
       in the shared stylesheets. Moved from
       bin/check-css.php Pass 3.

    2. Views must not hardcode pixel widths above
       375px on inline style attributes. The
       platform's smallest target is 375px. A fixed
       width above it prevents the element from
       shrinking below the viewport. New rule.

    3. <table> elements in admin views must sit
       inside a wrapper that carries
       data-responsive="scroll" or
       data-responsive="cards". Moved from
       bin/check-html.php W1, flipped from a
       warning to a hard error.

  tables use per-table styling rather than the

## Decisions made

- **Rule 3 is scoped to admin views.** The storefront
  does not use the data-responsive treatment system.
  Scoping the check to resources/views/admin/ avoids
  the false positives that W1 currently produced.
  The storefront's own tables (claims, product specs)
  are the only two tables in the codebase not on the
  treatment system, and they were never meant to be.

- **Rule 2 scans inline style attributes only, not
  <style> blocks.** A width in a `<style>` block
  rule is in a CSS context where selectors matter. A
  width in an inline `style="..."` attribute is on
  the element that has to fit. The narrower rule is
  precise. If a future pass wants broader coverage,
  it extends rule 2 to parse `<style>` block rules.

- **The Bootstrap <div class="row"> rule was dropped.**
  The plan named it as a soft warning "until the
  audit is complete." The audit is not complete, and
  the grep for `.row` finds 148 instances. Most are
  legitimate Bootstrap grid usage. A soft warning on
  148 lines is noise. The concern the rule tried to
  address - grids that do not collapse at the plan's
  breakpoints - is caught by the browser test, not
  by a static checker.

- **The @media rule moved from check-css.php to
  check-responsive.php.** The rule is about the
  responsive contract, not the CSS structural
  integrity. Its new home is thematically correct.

- **The W1 rule moved and flipped.** It was a warning
  in check-html.php because the data-responsive
  consumers did not exist yet. They do now. The rule
  belongs with the responsive contract, and it should
  be a hard error.

## New patterns for REMEMBER.md

**A checker's scope is a design decision, not an
accident.**

Rule 3 checks admin views only. That is not a
limitation. It is a deliberate scope: the
storefront uses a different table system. The
checker enforces the contract that exists, not
the contract that might exist.

The same rule applies to check-theme.php (theme
variables only), check-css.php (CSS structure
only), and check-html.php (HTML structure only).
Each checker has a defined scope. When adding
rules to an existing checker, ask whether the rule
belongs to its scope or to another checker's.

**Moving a rule between checkers is a one-time
change; duplicating it is permanent drift.**

Rule 1 and rule 3 moved from existing checkers
into check-responsive.php. They were removed from
their old homes in the same commit. If they had
been added to the new checker without removing
them from the old ones, the same violation would
be reported twice and the two would eventually
diverge.

The same applies to the aggregator entry: the CSS
checker's description was updated in the same
commit that moved the @media rule out of it.
