## Bugs found

1. **View parameter name collision.** `View::renderFile()`
   parameters `$name` and `$data` shadowed any view
   variable of the same name because `extract(...,
   EXTR_SKIP)` will not overwrite a parameter already in
   scope. The accept-invite view greeted the invitee with
   "Welcome, admin.users.accept-invite." Fixed by renaming
   the parameters. Commit `44db2bc`.

2. **Post-invite redirect landed on `/` instead of
   `/login`.** The invitee set their password, submitted,
   and the browser went to the storefront home instead of
   the login form. Two causes:
   - `GuestMiddleware` default redirect target is `/`.
     When an admin (or a browser with a live admin
     session) visited `/login`, the middleware bounced
     to `/`.
   - The invite-accept flow did not clear a pre-existing
     session, so the invitee could arrive with an admin
     cookie still present.
   Fixed by binding `GuestMiddleware` with the admin
   dashboard target and by adding `Auth::logout()` in
   `completeInvite()`. Documented as Pattern 35.

3. **Duplicated `absoluteUrl()` in two controllers.** Same
   logic, same hardcoded `'localhost:8084'` fallback.
   The fallback happened to match the current dev
   environment, so it did not manifest, but it was a
   latent bug for any future deployment. Fixed by
   extracting `Platform\Support\AppUrl::absolute()`.

No bugs found during the initial user-management build;
the two that surfaced were on the redirect side.

## Decisions made

- **Two feature commits, not three.** The password reset,
  sign-out page, and redirect fixes all live in
  `AuthController.php`. Splitting by hunk would have
  created three commits that each broke the file for the
  next one. Bundled as `5c156cb`.

- **`GuestMiddleware` bound per-product.** Platform
  default `'/'` is correct for a generic product.
  Commerce overrides with `/commerce/ca-admin`. The
  middleware stays product-agnostic; the product declares
  its audience.

- **`AppUrl` helper in Platform, not Commerce.** Both
  audiences need absolute URLs for emails. One helper,
  one source of truth, no per-audience duplication.

- **`config/app.php` `url` default set to
  `http://localhost:8084`.** Dev environment default.
  Documented that `config/local.php` overrides in
  production.

- **Storefront logout unchanged.** Still redirects to
  `/` with a flash. The dedicated `/logout/done` page
  is admin-only by design.

- **PHPStan level stays at 8.** No move to level 9.
  Level 9 would require thousands of `mixed` narrowing
  annotations across the codebase with negligible new
  bug detection. Decision recorded in this session.

## New patterns
