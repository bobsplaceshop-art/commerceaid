## Decisions made

- **Revert the checkout guard, do not keep it.**
  Speculative fixes on passing surfaces are the class
  of change the "browser test first" discipline exists
  to prevent. The browser test passed. The guard is
  removed.

- **Theme the offline page, do not leave it light-only.**
  The error pages are theme-aware. The offline page is
  the same class of surface (a fallback shown outside
  the normal request flow). It should match.

- **Match the sibling pattern exactly.** The offline
  page uses the identical <html data-theme>, pre-paint
  script, and main-v2.css link as 403.php. One theme
  mechanism, one localStorage key, one place to
  maintain.

- **Keep the two radial gradients inline.** main-v2.css
  has no variable for a body background-image. The
  gradients are low-opacity translucencies that read
  on both light and dark --ra-bg. Binding them to a
  variable that does not exist would be wrong.

- **Keep the box-shadow hardcoded.** main-v2.css
  defines --ra-shadow-lg as a single-layer shadow
  (0 20px 60px rgba(15,23,42,.15)). The offline card
  uses a two-layer shadow. No variable matches the
  shape. Leave it inline.

- **The storefront tail item closes as not-applicable.**
  The storefront is light-only by design. The docblock
  says so. The session file records the finding. No
  code change.

## New patterns for REMEMBER.md

**The prevenger's CSS structural checker catches
multi-line declarations that PHP lint and PHPStan
cannot see.**

A multi-line CSS declaration inside an inline <style>
block is valid CSS but violates the parser's line-
based rule. Every declaration in the codebase is
one-line. When writing a new <style> block, match
that convention. Multi-line property values across
the codebase do not exist and would be flagged.

The specific failure: bin/check-css.php inspects each
line ending with `:` or with a value that has no
terminating `;`. A declaration split across multiple
lines triggers "Declaration missing terminating
semicolon".

The fix is mechanical: collapse to one line. Colors,
fallbacks, and argument order are preserved.

**The storefront is light-only. Do not assume the
admin theme key reaches it.**

The admin writes localStorage['ra-theme'].
The storefront does not read it. The error pages and
the offline page do read it (matching the admin's
theme). The storefront itself does not.

When working on a storefront surface, read the
storefront layout's docblock before assuming it
inherits any admin setting. Line 34 of
resources/views/storefront/layouts/main.php names
this explicitly.
