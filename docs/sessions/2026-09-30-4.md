## Bugs found

Two real bugs, both fixed.

1. **FileValidator rejected WebP.**

   The ALLOWED allowlist had no 'webp' entry. Uploading
   a WebP (which the pipeline itself produces) returned
   422 "contents do not match extension". The pipeline
   could not accept its own output. Fixed by adding
   `'webp' => ['image/webp']` to the allowlist.

   This bug had been latent since 008G.4a shipped.

2. **Featured and New arrival toggles always read as off.**

   The inline $val / $valBool closures in
   products/edit.php used $product->$key with the
   caller's snake_case key. The Product model uses
   camelCase. $product->is_featured returned null.
   $valBool returned false regardless of the DB value.

   Exactly Pattern 15 in docs/REMEMBER.md. The
   EditView::valClosure / valBoolClosure helpers exist
   to prevent this. The product editor had not been
   migrated. Fixed by swapping the two inline closures
   to EditView calls.

   Also deferred: five other admin views still use the
   inline closures (attributes, brands, categories,
   customer_groups x2). Migration to EditView is a
   hygiene pass.

3. **Sequencing regression: helpers not on disk when
   the consumer landed.**

   First File 15 attempt anchored on a function name
   that was not present. The patch script's
   sys.exit(1) fired; the helper was not written. The
   card partial was changed anyway (File 16). Every
   product card on the storefront silently vanished -
   view_partial() caught the resulting fatal and
   returned an empty string.

   Caught by the operator's browser test and the app
   log:

     ERROR: view_partial(..._product-card) failed:
     Call to undefined function product_picture_url()

   Recovered by reverting File 16, re-running File 15
   with a corrected anchor and immediate grep
   verification, then re-applying File 16.

   This is a real process failure, not a code bug.
   Documented as an extension to Pattern 20 in
   docs/REMEMBER.md.

4. **Placeholder SVGs not written.**

   The same File 15 script wrote two SVG heredocs to
   public/assets/img/. The directory did not exist (or
   the heredocs did not run for some other reason).
   `cat >` fails silently if the parent directory does
   not exist. The placeholder fetch returned 404.

   Fixed by `mkdir -p public/assets/img` then
   re-writing the SVGs. Verified with `ls -la` and a
   browser fetch (HTTP 200).

   Also folded into the Pattern 20 extension.

## Decisions made

- **Local placeholders, not picsum.** Retire the
  external image origin. Use
  /assets/img/product-placeholder.svg and
  /assets/img/category-placeholder.svg. Deterministic,
  self-hosted, works offline.

- **CSP unchanged for now.** The home.php promo blocks
  still use picsum, so the img-src directive keeps
  picsum.photos. The CSP tightens when the theme
  customizer wires the promo blocks to real images.

- **Plain <img>, no <picture>.** Every variant is a
  WebP. Modern browsers all support it. No JPEG
  fallback source. The admin preview uses <picture>
  for the same reason it always has; the storefront
  does not.

- **Variant choices per surface.**
  - Product card: card (400x500)
  - Product detail hero: lg (1200x1500)
  - Product detail thumb: card (400x500)
  - Product detail thumb large: lg (1200x1500)
  - Category card grid: md (800x800)
  - Category hero: lg (1600x1600), CSS-cropped to 3:1
  - Wishlist/recent: card (400x500)

- **Product detail layout.**
  - Media column bounded at 420px max-width.
  - Hero aspect 4:5.
  - Thumbnails horizontal scroll, 72px fixed width.
  - Product title 1.75rem desktop, 1.3rem mobile,
    3-line clamp for extreme cases.

- **Category wide variant deferred.** The current
  `lg` (1600x1600) square variant is CSS-cropped into
  the 3:1 hero banner. Works for now. A future small
  stage adds a wide (1600x600) variant to
  MediaVariantSet::categoryImage() so the hero
  preserves the composition of square sources.

- **Variant-images section is Session 4.** The Images
  tab gets a dedicated "Variant images" card for
  assigning one image per Color value. The gallery
  holds only product photos (no attribute_value_id).
  The two concepts are separate. Size axis does not
  get swatch images - only color.

## Next session opens with

**Session 4 of 008G.4a.2 - Variant images section.**

Scope (locked earlier in this session):

1. The Images tab in the product editor gains a second
   card: "Variant images".
2. It renders one slot per Color value. Only Color
   axes (attribute name contains "color" or "colour").
   Size does not get slots.
3. Each slot accepts an upload or a picker selection.
4. The picker modal learns a "target" concept:
   gallery vs specific attribute value.
5. syncImages() reads a new variant_images[] POST
   array and creates rows with attribute_value_id
   set.
6. Storefront: the product detail page's variant
   selector becomes a swatch row. Each swatch shows
   its assigned image as a mini-thumbnail. Clicking
   a swatch swaps the hero image.

Read before writing:
  - app/Commerce/Controllers/Admin/ProductController.php
    syncImages() (already read this session)
  - resources/views/admin/products/_tab_images.php
    (the current shape)
  - resources/views/storefront/product/show.php
    (the variant selector block)
  - app/Commerce/Support/MediaVariantSet.php
    (the attribute_value_id semantics)
