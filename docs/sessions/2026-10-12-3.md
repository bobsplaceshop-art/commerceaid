## Decisions made

- **Slug immutability after publish.** A published
  form's URL is a public reference; changing it would
  break every external link. The slug is editable in
  draft state only. The edit view renders the slug
  input as readonly when the form is not a draft, and
  the service refuses the change with a clear error if
  a stale POST tries to change it anyway.

- **Publish requires at least one field.** A published
  form with no fields produces a public URL that
  renders nothing. The service refuses with "Add at
  least one field before publishing the form." The
  edit view shows the flash in red, keeping the form
  in draft.

- **Duplicate clones fields, not submissions.** A
  copy of a form should not inherit the original's
  history. The new form has the same fields, a
  `-copy` slug, and zero submissions.

- **Soft delete, not hard delete.** The
  `commerce_forms` table has a `deleted_at` column.
  Deleting a form hides it from every list and stops
  the public URL, but the row and its submissions stay
  for audit.

- **Status tab counts are search-aware but not
  status-aware.** The numbers reflect the active search
  (so a search for "copy" shows All (1) even though the
  full list has more), but they ignore the active
  status filter. That way the tab bar shows how many
  results are in each status without changing the
  numbers as the merchant switches tabs.

- **`LIKE '%term%'` for search, storewide.** The
  product catalog uses it, and forms use it too.
  Fulltext search (MATCH ... AGAINST) would need an
  index and a migration for a table that will never
  have enough rows to justify it. `LIKE` is consistent
  across the codebase.

- **Session split confirmed.** Session 2 became 2a
  (form CRUD) and 2b (field editor). The field editor
  is a substantial UI with type-conditional config,
  option management for select/radio/checkbox, and
  reorder controls. It deserves its own session and
  its own verification.

## Session in the larger arc

Stage 009 now has a working admin surface. The merchant
can create, edit, publish, unpublish, archive,
duplicate, and delete forms. The public surface (GET
/forms/{slug}) and the submission pipeline ship in
Sessions 3 and 4.

The demo form created during the browser test was
deleted after testing, so the database is clean. The
`commerce_forms` table holds zero rows; the
`commerce_form_fields` and `commerce_form_submissions`
tables hold zero rows.

Stage 009's reuse of the CustomFields input type
registry paid off twice in this session. First, the
`duplicate()` method's field copy loop uses
`field->inputType`, `field->options`, and
`field->constraints` — all shapes the registry
already defines. Second, the field editor in Session
2b will render each type's config UI directly from
`InputType::configFields()`, with no per-type UI code
in the controller or view.

PHPStan level 8 remains clean at 256 files. Zero
baseline, zero suppressions.
