  `_variant-row.php` rendered the number input with
  `class="ra-form-control text-end"`. The class is
  defined only inside the storefront's `.sf-forms`

  every other admin input uses. That class is
  defined in `main-v2.css` (with `width: 100%`)
  and in the Bootstrap stylesheet.

## Decisions made

- **settings/index stays on scroll.** A key-value
  table with two data columns fits at 375. Cards
  would put Key and Value on separate rows,
  doubling the vertical height with no readability
  gain.

- **The cascade check added the upstream direction
  that caught the partial.** The downstream read
  alone would have missed the `_variant-row.php`
  dependency. The four-direction rule worked as
  intended.

- **The `form-control` fix is one class change, not a
  shared rule.** `ra-form-control` is used in exactly
  one place. Adding an admin-scope rule for a class
  that appears once is worse than using the class
  that already exists.

## New patterns for REMEMBER.md

**The upstream cascade direction surfaces partial
dependencies that the downstream direction misses.**

A downstream grep for a view finds the files that
include it. An upstream read of the view finds the
files it includes. A `<td>` may live in either
file. When the table body comes from a partial,
the wrapper attribute lives in the parent and the
cell labels live in the partial. Both need to be
in the same patch.

**A CSS class defined only inside a scoped
container is inert outside that container.**

`.sf-forms .ra-form-control` styles nothing on a
page that has no `.sf-forms` ancestor. The class
looks defined in `grep`, but the effective rule
requires an ancestor that does not exist. When a
class is inherited from another codebase or copied
from a scoped context, verify the ancestor chain
before assuming the styling applies.
