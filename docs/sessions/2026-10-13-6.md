- **The cascade check became a standing rule.**
  Four directions, run before every patch:

    Downstream  who calls this? grep the touched
                symbols across app/, resources/,
                public/.
    Upstream    what does this depend on? read the
                CSS, JS, config the patch relies on.
    Siblings    what else is like this? grep the
                pattern across all similar files.
    Perpendicular  what is the current state? read
                the exact bytes at the patch site,
                byte for byte.

  Only after all four does the patch get written.

## Bugs found

1. **Tab strips wrapped instead of scrolling.**
   Four separate class families all had the same
   problem: `flex-wrap: wrap` at desktop, no
   horizontal-scroll fallback at narrow widths.
   Fixed by adding an `overflow-x: auto` + hidden
   scrollbar rule at `max-width: 899px` for each.
   Fixed in `e2ed540`.

2. **Setup nav overflowed the viewport instead of
   scrolling inside itself.** `.ra-setup-nav-list`
   had `overflow-x: auto`, but the parent grid column
   could not shrink below its content. Fixed by
   adding `min-width: 0` to `.ra-setup-nav`. Fixed in
   `e2ed540`.

3. **Store Settings tabs showed a scrollbar.** The
   `.ra-settings-tabs` rule had `overflow-x: auto`
   but no scrollbar-hidden rule. Fixed by adding
   `scrollbar-width: none` and `::-webkit-scrollbar
   { display: none }`. Fixed in `e2ed540`.

4. **Four admin views had inline `<style>` blocks
   with grid rules.** Every one used `auto-fit` or
   `auto-fill` with `minmax()`, and none had a
   media-query fallback. Fixed by moving the rules
   to `main-v2.css` and adding a shared mobile
   fallback. Fixed in `e2ed540`.

5. **Sixteen list tables showed a vestigial
   scrollbar.** Every wrapper was on
   `data-responsive="scroll"` even when the table
   content fit at every width. The scrollbar was
   harmless but visually noisy. Fixed by converting
   to `data-responsive="cards"` across three
   batches. Fixed in `923aef3`, `0454eec`, `f82aeaf`.

## Decisions made

- **Every admin list table uses the card treatment.**
  Detail-page tables (key-value lists inside a
  resource detail view) may stay on scroll. The
  distinction: a list of records is cards. A
  two-column spec list is scroll.

- **Hidden cells carry both attributes.** Cells with
  `class="ra-hide-sm"` are display: none below 899,
  so their `data-col` value has no visual effect.
  But every cell carries `data-label` and `data-col`
  for consistency - if the hiding rule is ever
  changed, the card treatment is ready.

- **The grid fallback lives in main-v2.css, not in
  views.** The `@media (max-width: 639px)` block
  that drops the four tile grids to `1fr` is shared.
  Any future tile grid gets the same treatment
  without adding its own inline rule.

- **Two redundant overrides were dropped during the
  move.** dashboard.php's `.ra-btn-sm` (0.05rem
  padding difference) and inventory/index.php's
  `.ra-badge-danger` (hardcoded colors instead of
  theme tokens). The canonical rules in
  main-v2.css already handle both, and the badge
  rule uses `--ra-error-bg` / `--ra-error-fg`
  which are theme-aware.

- **Batch-splitting the table conversion.** Sixteen
  views is too many for one commit. Three batches
  of 5/5/6. Each batch is a read-then-patch pass
  with its own browser test and its own commit.

- **The tab strip fix pattern is "scroll, not
  wrap".** Not "hide the tabs". The user scrolls
  to see the hidden ones. The scrollbar itself is
  hidden so the strip reads as a frameless row of
  pills.

## New patterns for REMEMBER.md

**The cascade check has four directions, and it
runs before every patch.**

Stated in full in the Worked-on section. The rule:
downstream, upstream, siblings, perpendicular. If
any direction returns something unexpected, the
patch is not written. This became standing
practice during this session after a series of
misses that each lived in one of the four
directions.

**A class name with a suffix family needs a
boundary-anchored grep.**

`ra-color-swatch` is not the same as
`ra-color-swatch-lg`. A grep for `ra-color-swatch`
matches both. In a cascade check, that produces a
false positive: the class appears to be shared
when it is not. Use `grep -rn '\bra-color-swatch\b'`
to match only the exact class. Same rule for
`ra-actions-cell` versus `ra-actions-cell-something`
(if such a class ever exists), and any other name
with a prefix family.

**Python triple-single-quoted strings cannot
contain `''` adjacent to the terminator.**

A Python heredoc that embeds PHP code often needs
to quote the PHP empty string - `''`. When that
sequence appears at the end of a triple-single-
quoted Python string, the Python parser reads it
as `''` (string close) followed by a stray `''`
that starts a new string. The result is a
SyntaxError at parse time.

Two workarounds:
  - Use triple-double-quotes for the anchor and
    stop the anchor before the `''` (so the Python
    string ends at a space or a different character).
  - Use single-quoted Python strings with the
    single quotes escaped: `'... \'\' ...'`.

The batch-3 script aborted on this exact problem.
Fixed by switching the affected anchor to
triple-double-quotes and truncating the anchor
before the PHP `''`.
