## Bugs found

Not code bugs. Documentation bugs. Both were caught
before commit.

1. **Invented permission count in the STATUS draft.**
   The draft I wrote said "53 across 12 modules" and
   "Pre-009 the count was 49; the four new forms.*
   slugs bring it to 53." The number was made up. The

   The arithmetic that would have been correct:

   (forms, 0017) = 67. The old "49 across 11 modules"
   was accurate before the pricing engine shipped. It
   was stale by six modules and eighteen slugs.

2. **False "awaiting close" paragraph in the ROADMAP
   draft.** The draft said 008K.5 was "code complete,
   awaiting only the close commit." The close had
   already happened on 2026-10-11. The tag existed.
   The commit `05ea229` had already updated the
   ROADMAP and STATUS for the close. My draft would
   have re-opened a closed stage.

   Caught by `git tag -l 'stage-*'` and `git log
   --oneline --all | grep 008k.5`.

Neither bug reached the repository. Both were caught
by reading the actual state (the database, the git
history) before writing the document.

## The rule that was learned and re-applied

**Read the code, then write. Never write against
memory.**

Stated by the operator at the opening of this session
after the previous session's docs pass had made the
same class of mistake (an invented permission count,
a false "waiting for close" statement). Applied
consistently this session:

  - Wrote nothing until `git log` showed what had
    actually shipped.
  - Wrote no permission count until a database query
    returned one.
  - Wrote no completed-stages rows until the migrations
    and git tags confirmed the dates.
  - Deleted the diagnostic script after its job was
    done.

The session file for 2026-10-12-5 already recorded the
same discipline as a working pattern. This session is
the second instance where the discipline prevented a
wrong commit.
